# Flak Heaven: где теряем время и как ускориться

Разбор от 16.10.2026 по фактической истории проекта: 22 треда, 23 PR (21 слит), журнал проекта, память проекта, код в `main`.
Ничего в настройках и коде не менялось, это только предложения. Решение по каждому пункту за тобой.

## Коротко

Работа тормозит не из-за самих инструментов (Meshy, Blender, Godot работают), а из-за четырёх вещей:

1. **Лимит использования Claude.** Треды дважды вставали на лимите: 15.10 в 17:30 (на 69 минут) и 16.10 в 18:33. Пять тредов на самой сильной модели одновременно гоняют длинные автотесты, и лимит заканчивается к вечеру.
2. **Автотест 15–30+ минут на каждую правку.** В ночь на 16.10 три треда одновременно ждали автотестов, а ты спрашивала, почему треды неактивны.
3. **Каждый PR ждёт твоего клика, а ветки конфликтуют.** За 14–16.10 слито 19 PR, и четыре раза пришлось отдельно сливать `main` в ветку, в том числе из-за `player.gd` (1248 строк, его правят сразу 3–4 треда).
4. **Ручная передача данных.** Логи с ПК ты прикладываешь вручную, портреты рисуешь в ChatGPT вручную, кросс-проверку GPT копируешь вручную, статус по правкам просила трижды за день.

Плюс один организационный сбой: решение «бой в 3D» от 14.10 два дня не было ни в одном треде.

### 1. Модели по ролям, чтобы не упираться в лимит

**Что происходит.** Сейчас почти все треды на самой сильной модели и работают параллельно. Лимит кончался дважды за два дня, оба раза вечером, когда ты как раз смотришь результаты.

**Что предлагаю.**
- Сильная модель только для кода игры, геймдизайна и 3D-моделей в Blender.
- Лёгкая модель (Sonnet) для статусов, сводок, планёрки, документов и PDF, чек-листа, сборки архивов. Планёрка и итоги недели уже на ней.
- Не больше 3 тредов, которые одновременно пишут код. Остальные ждут в очереди, а не работают параллельно и не конфликтуют.
- Автотесты запускать в фоне и не держать тред «живым» всё время теста (это само по себе съедает лимит).

**Что от тебя.** Ничего: ты разрешила Claude переключать модели самому. Если лимит всё равно будет заканчиваться, можно включить дополнительное использование на странице [Использование](https://claude.ai/settings/usage). Это расходы, решение твоё.

### 2. Готовая среда для тредов

**Что происходит.** Каждый новый тред стартует на чистой машине и заново скачивает Godot 4.4.1 и шаблоны экспорта с GitHub, ставит `bpy` (Blender), `pymeshlab`, `trimesh`, `libopengl0`. Это 5–10 минут и иногда сбои ещё до начала работы.

**Что предлагаю.** Скрипт установки в настройках облачной среды: всё это ставится один раз при старте треда. Скрипт я подготовлю отдельным файлом, когда скажешь «да».

**Что от тебя.** Открыть [Настройки проекта](#project-settings/environment) → меню «Облачная среда» → шестерёнка у выбранной среды → поле «Скрипт установки» (Setup script), вставить туда скрипт и сохранить. Сработает в новых тредах.

### 3. Быстрый автотест

**Что происходит.** `--autotest --fast` прогоняет полный вылет за все три класса. В облаке без видеокарты это 15–30+ минут, и тред всё это время ждёт. При этом FPS в облаке всё равно ничего не значит.

**Что предлагаю.**
- Режим `--smoke`: один класс, 2–3 минуты боя, проверка, что нет ошибок скрипта, и пара скриншотов. Его гонять после каждой правки.
- Полный автотест за три класса только один раз перед открытием PR.
- Если правка не трогает бой (меню, ангар, документы), достаточно проверки синтаксиса (`--import`), без вылета.

**Что от тебя.** Ничего, это небольшая правка в `main_debug.gd`. Сделает любой тред с кодом, если скажешь «да».

### 4. Разделить `player.gd` на модули

**Что происходит.** В `player.gd` 1248 строк: полёт, оружие, ведомые, топливо, «Нырок», точки стрельбы. Его одновременно правят «Итоги теста», «ИИ врагов», «Прокачка» и «3D и биом». Отсюда коммиты «слияние main в ветку» и риск сломать чужую правку. Разделение `main.gd` и `hud.gd` (PR #4) уже показало, что это помогает.

**Что предлагаю.** Вынести из `player.gd` стрельбу и оружие, ведомых и топливо в отдельные файлы, без изменения поведения. Лучше сделать сразу после слияния PR #22, пока других открытых веток с `player.gd` мало.

**Что от тебя.** «Да» на задачу.

### 5. Одна общая ветка и одно слияние в день

**Что происходит.** Claude не может сливать PR без ревью на GitHub, поэтому каждый PR ждёт тебя. 15–16.10 ты слила 12 PR, а пока один ждёт, следующий успевает с ним разойтись.

**Что предлагаю.** Завести ветку `next`. Треды сливают свою работу в `next` сами (это обычный push, ему твой клик не нужен) и сразу решают конфликты между собой. Ты раз в день (или перед тестовой сборкой) сливаешь один PR `next` → `main`, где в описании перечислено всё, что вошло. `main` остаётся рабочей версией, как сейчас.

**Что от тебя.** «Да» на правило: это меняет раздел «Как работать вдвоём» в `CLAUDE.md`. Потом раз в день один клик: в PR внизу страницы зелёная кнопка «Merge pull request», затем «Confirm merge».

### 6. Автопроверка на GitHub

**Что происходит.** Проверок на GitHub нет. О том, что PR что-то ломает, узнаём только из автотеста внутри треда.

**Что предлагаю.** GitHub Actions на каждый PR: скачать Godot 4.4.1, `--import` и быстрый автотест из пункта 3 без окна. Результат будет зелёной или красной галочкой прямо в PR, и тред сам исправляет красную. Для личного репозитория это бесплатно в пределах 2000 минут в месяц.

**Что от тебя.** «Да» на задачу. Проверить, что Actions включены: [Настройки Actions репозитория](https://github.com/kanta201196-hub/FlakHeaven/settings/actions) → «Allow all actions and reusable workflows» → «Save».

### 7. Лог вылета уходит сам вместе с отчётом

**Что происходит.** Отчёт тестера (`report.gd`) уже уходит в Google Таблицу, но в нём только анкета, статистика и 150 строк журнала Godot. Полный лог `playtest_log*` ты ищешь в `%APPDATA%` и прикладываешь руками, а другие тестеры этого делать не будут.

**Что предлагаю.** В отчёт добавить сжатый лог последних вылетов (метрики FPS, 3D, ИИ врагов). Таблица уже принимает запросы, нужно только новое поле в Apps Script. Тогда данные с реальных ПК, единственные, по которым можно судить о производительности, приходят без ручной работы.

**Что от тебя.** Ничего до следующей тестовой сборки. Обновить Apps Script придётся тебе (это твоя таблица); скрипт и пошаговую инструкцию со ссылкой подготовит тред.

### 8. Треды сами читают отчёты тестеров

**Что происходит.** Отчёты лежат в Google Таблице, а Claude видит их только если их переслать.

**Что предлагаю.** В проекте уже подключён Google Drive. Тред, который разбирает тест, сам открывает таблицу и сводит отчёты.

**Что от тебя.** Ничего. Если таблица не найдётся поиском, прислать на неё ссылку.

### 9. Один живой файл статуса

**Что происходит.** 16.10 ты трижды просила актуализировать статусы («Статус правок», «актуализируй статусы по задачам», раньше «почему треды неактивны»). Каждый раз это отдельная работа и расход лимита.

**Что предлагаю.** Файл [status.md](docs/playtest/3.4-t1/status.md) уже есть. Сделать правилом: каждый тред обновляет свою строку при открытии и слиянии PR. Тогда актуальный статус всегда в одном месте, а запрос «актуализируй» превращается в короткий ответ без поиска по тредам.

**Что от тебя.** Ничего.

### 10. У каждого решения есть исполнитель

**Что происходит.** «Бой в 3D» решили 14.10, но ни один тред его не взял, и это всплыло только 16.10.

**Что предлагаю.** В журнале решений `docs/game-context.md` у каждой записи есть номер задачи в бэклоге и тред-владелец. Планёрка раз в день проверяет решения без владельца и пишет о них одной строкой.

**Что от тебя.** Ничего.

### 11. Настроить Gemini

**Что происходит.** Подписка на Gemini есть, но не настроена. Портреты ты делаешь в ChatGPT вручную, кросс-проверку в GPT тоже копируешь вручную.

**Что предлагаю.** Ключ Gemini API в среде проекта. Тогда треды сами могут: генерировать концепт-картинки и референсы перед тратой кредитов Meshy, делать варианты портретов по твоему промпту (финальный выбор за тобой), прогонять кросс-проверку документов вторым мнением. Важно: подписка в приложении Gemini и API это разные вещи, для API нужен ключ из AI Studio, у бесплатного уровня есть лимиты.

**Что от тебя.**
1. Создать ключ на [Google AI Studio](https://aistudio.google.com/apikey) → «Create API key».
2. В [Настройках проекта](#project-settings/environment) → меню «Облачная среда» → шестерёнка → переменные окружения: добавить `GEMINI_API_KEY=<ключ>`, а в сетевой доступ добавить `generativelanguage.googleapis.com`.

### 12. Беречь кредиты Meshy

**Что происходит.** Осталось 244 кредита, это около 8 моделей. Простые детали из Meshy выходили плохо (турели), и их пришлось переделывать в Blender по твоим фото.

**Что предлагаю.**
- Meshy только для сложных форм (самолёты, крупная техника). Турели, оружие, ракеты, наземное ПВО делать в Blender по референсам, как уже договорились.
- Перед запуском в Meshy утверждать входную картинку (вид, без опознавательных знаков, силуэт «по мотивам»), чтобы не тратить 30 кредитов на заведомо неверную модель.
- Проверять баланс перед пакетом и писать в треде, сколько уйдёт.

**Что от тебя.** Ничего. Отдельно, до страницы в Steam: проверить условия коммерческого использования Meshy на твоём тарифе (это уже в [чек-листе](docs/owner-checklist/checklist.md)).

### 13. Компьютер по умолчанию

**Что происходит.** У тебя настроено несколько компьютеров, и ни один не выбран основным. Поэтому карточки подключения папки не срабатывали, и логи ты прикладываешь сама.

**Что предлагаю.** Выбрать один компьютер, на котором ты играешь в тестовые сборки. Тогда тред сможет сам забирать логи из папки игры (с твоего разрешения на эту папку) и класть туда .blend-файлы.

**Что от тебя.** Написать в этом треде, какой компьютер основной (как он называется в приложении Claude). После пункта 7 это нужно реже, но пригодится для .blend и больших файлов.
