# Как работает команда (процесс)

Состав: **Kirill** — руководитель проекта (финальные решения, юр./фин. вопросы, сборка и игра в билды, генерация картинок в NanoBanana). **ИИ-агенты** — роли, которые выполняет Claude по брифам из `claude/team/`. **Фрилансеры** — музыка/звук, консультации дизайнера (по мере надобности).

## Кто кем управляет
```
Kirill ──(цели, решения, вето)──► PM-агент ──(задачи)──► Продюсер · Геймдизайнер · Арт-директор · Аналитик · Программист
   ▲                                   │
   └──(статус, вопросы на решение)─────┘
```
- **PM** ведёт бэклог и спринт, раздаёт задачи ролям, проверяет результат по критериям готовности, обновляет документы, докладывает Kirill.
- **Продюсер** отвечает за «что и когда»: дорожная карта, масштаб, бюджет, стратегия Steam. PM отвечает за «как и кто»: выполнение.
- Роли не спорят напрямую: разногласия PM выносит Kirill с вариантами и рекомендацией.

## Единый источник правды (документы проекта)
| Документ | Что в нём | Кто обновляет |
| --- | --- | --- |
| `claude/game-context.md` | Решения по игре + журнал решений | PM после решения Kirill |
| `claude/backlog.md` | Все задачи, спринт, статусы, владельцы | PM |
| `claude/team/*.md` | Брифы ролей | PM (с согласия Kirill) |
| `claude/status-log.md` | Короткие отчёты по итогам спринтов | PM |
| Концепт-документ (Claude Docs) | Подробный геймдизайн | Геймдизайнер через PM |
| Код прототипа (архив + папка proto) | Сборки | Программист |

## Цикл (спринт = 1 неделя или 1 сборка)
1. **Планирование** (Kirill: «планёрка» / «что дальше»): PM показывает статус, предлагает цель спринта и 5–8 задач. Kirill утверждает или правит.
2. **Выполнение**: PM запускает роли (параллельно, где задачи независимы), собирает результаты.
3. **Проверка**: PM сверяет каждый результат с критерием готовности; недоделанное возвращает роли один раз, дальше — выносит Kirill.
4. **Ревью** (Kirill играет / читает): отзыв → новые задачи в бэклог.
5. **Итог**: PM обновляет бэклог, журнал решений, `status-log.md`.

## Статусы задач
`идея` → `в бэклоге` → `в спринте` → `в работе` → `на проверке` (PM) → `ждёт Kirill` → `готово` · или `заблокировано (причина)`.

## Что решает только Kirill
Юридическое и финансовое; бюджет и найм фрилансеров; цена и дата релиза; изменения в «Чего НЕ делаем» и масштабе; финальное «да» по геймдизайну, арту и звуку. Агенты готовят варианты и рекомендацию, но не решают.

## Критерий готовности (общий)
Результат лежит в проекте (документ / файл / сборка), понятен без чата, проверен (код — автотест без ошибок; документ — сверен с game-context), в бэклоге отмечен, решения записаны в журнал.

## Ограничения агентов (честно)
Агенты работают, пока открыта сессия Claude в этом проекте. Сами по расписанию они не просыпаются — для этого можно завести запланированную задачу (например, еженедельный статус). Играть в билд, слушать звук и генерировать картинки они не могут — это делает Kirill.

## Правило Kirill (10.10.2026)
- **Новую сборку (архив версии) делаем только по прямой задаче Kirill.** Если задачи на сборку не было — сначала спросить («собрать 2.x сейчас или копим изменения?»). Подготовка файлов, обработка картинок, промпты, превью — без вопросов.
