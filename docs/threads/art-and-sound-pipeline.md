# Арт и звук: как это делается сейчас (на 17.10.2026)

Сводка для Kanta и его Claude: откуда берутся модели, текстуры, портреты и звук, какие у них лицензии, какие инструменты и подписки используются и что не получилось. Источники — треды проекта Claude у Kirill (выжимки рядом, в `docs/threads/`), код в `main` и ветка PR #22.

Тяжёлые файлы (сырые модели, .blend, скриншоты, портреты в полном размере) лежат не в репозитории, а в файлах проекта Claude у Kirill, `/mnt/project-files/`. Их опись — `/mnt/project-files/export/heavy-files-inventory.md`, архив для Kanta — `/mnt/project-files/export/for-kanta-1…4-*.zip` (модели сырые, модели HQ, биом, .blend + скриншоты + портреты + референсы).

## 1. Общие правила, которые действуют на любой арт

- **Вымышленный мир** (CLAUDE.md, правило 4): никаких реальных стран, флагов, опознавательных знаков, названий реальной техники. Силуэты — «по мотивам» (решение 15.10). Знаки с фото-референсов в игру не переносим. Свои знаки и символы для кастомизации — в плане (решение 16.10 по каталогу, п. 1.2).
- **Два уровня качества** (решение 14.10, уточнено 15.10 и 16.10): в бою облегчённые модели (самолёт ~5–15 тыс. треугольников, текстуры до 2048), в ангаре и на крупных планах — максимальное качество (~100 тыс. треугольников, текстуры 4096). Облегчённые деревья и модели — только в пресетах «Качества графики» ниже «Максимального». На «Низком» бой остаётся на старых плоских спрайтах.
- **Каталог до моделей**: сначала список техники и оружия с картинками, замечания и референсы, потом модели (`docs/catalog/`).
- **Инструмент по типу объекта** (плейбук §6, принято 16.10): сложные формы (самолёты, крупная техника, скалы) — генератор Meshy; простые и точные детали (турели, подвесное оружие, ракеты, наземное ПВО) — Blender кодом по фото-референсам; портреты и концепты — ChatGPT/Gemini по промптам Claude; текстуры земли и камня — CC0.
- **Кредиты генератора бережём**: входную картинку и пакет генерации с расходом кредитов утверждает Kirill или Kanta до траты (CLAUDE.md, раздел «Арт и 3D»).
- **Предпросмотр из игровой камеры**: каждую модель показываем скриншотом так, как её увидит игрок (вид сверху / под наклоном 28°, рядом со спрайтом).
- **Производительность** оцениваем только по логам с реальных ПК: FPS в облаке без видеокарты ничего не значит.
- Стайл-гайды: `docs/sprint1/s1-08-art-styleguide.md` (2D, 10.10), `docs/sprint1/s4-style-guide-3d-biome.md` (3D-биом, B-37: свет, палитра, читаемость, уровни войны, бюджеты, запреты), правила ландшафта `docs/sprint1/s4-landscape-rules.md`.

## 2. 3D-модели

### 2.1. Соглашения (для всех GLB игры)
Из шапки `game/tools/model_lab/model_lab.gd`:
- нос по +X, верх по +Y (вид сверху — плоскость XZ), длина по X = 1.0 — игра масштабирует под длину спрайта;
- самолёты отцентрованы по высоте, наземное стоит на y = 0;
- подвижные части — отдельные узлы: `body`, `turret_1`, `barrel_1…`, `pylon_…`; у наземки `turret` / `launcher` / `antenna`, у заправщика `Boom`, `BoomTube`, `BoomTip`, у «Крепости» — узлы турелей, двигателей и люков (поля в `fortress.gd`, PR #26).

### 2.2. Генератор: Meshy (основной для сложных форм)
- **Решение 14.10** (Kirill): «Я оплатил Meshy, делаем модели там, лучшее качество и скорость». Платный план. Сравнивали с TRELLIS.2 и Hunyuan 3D (см. «Что не получилось»).
- **Вход**: игровой спрайт, увеличенный ×5, обрезанный, ~860 пикс. в квадрате 1024 на прозрачном фоне (`/mnt/project-files/pilot3d/inputs/`, `inputs.zip`). Эмблемы со спрайта убирать до генерации.
- **Как запускаем**: Claude генерирует сам через API (решение 14.10 20:08: «генерируй сам, неудачные модели сам не правь — я смотрю и даю комментарии»). Скрипты: `/mnt/project-files/pilot3d/meshy_tools/meshy_gen.py` (image-to-3D, `ai_model: latest`, текстуры + PBR) и `finish.py`; id задач — `meshy_api_tasks.json`. В репозитории этих скриптов нет.
- **Стоимость**: ~30 кредитов за модель. Баланс: 964 (14.10: 864 месячных + 100 постоянных) → 304 после биома (15.10) → 244 после заправщика и транспортника (16.10).
- **Доступ из облака**: `MESHY_API_KEY` в переменных среды, домены `api.meshy.ai`, `assets.meshy.ai`, `*.meshy.ai`.
- **Типичные ошибки Meshy**: принимает вид сверху за вид спереди — ЗРК пришёл колёсами вверх, бункер на боку (исправлено поворотом, без перегенерации); двигатели «Грача 1» вынесены вперёд к крылу; у «Осы 1» размах 0,68 вместо 0,75 (оставили). Сетки Meshy чистые; «чистка» в Blender — это правка вида по `docs/catalog/catalog.md` §8, а не ремонт сетки.
- **Что сделано в Meshy**: 6 самолётов игрока (кроме «Осы 2» — она из Hunyuan), 7 воздушных врагов, бункер, 10 элементов биома, заправщик, транспортник. ЗРК и РЛС из Meshy устарели — пересобраны в Blender.

### 2.3. Blender кодом (простые и точные детали)
- **Решение 16.10 16:40** (Kirill, после «турели выглядят неестественно» и «всё ещё очень плохо»): турели — модели по фото владельца в Blender, «Супер, давай использовать их»; дальше перерабатывать наши модели в Blender.
- Blender работает в облаке как Python-модуль `bpy` (`pip install bpy`, версия 5.x), без интерфейса. Готовые .blend прикладываются в тред — Kirill открывает их у себя в Blender.
- Скрипты — в ветке PR #22, папка `game/tools/blender/` (в `main` появятся после слияния):
  - `turret_lib.py` — общие примитивы с фаской, материалы, экспорт .blend + .glb, предпросмотр Cycles;
  - `turret_twin.py`, `turret_light.py`, `turret_tail.py` — турели «Кита» (спаренная, бронебашня, длинные стволы с дульными тормозами), «Грача» (низкая тумба, 2 коротких ствола один над другим), кормовая кабина стрелка «Кита» (остекление + шаровая спарка);
  - `weapons.py` — подвесное оружие по ступеням: ракеты В-В (`aam 1` средней дальности, `aam 2` ближнего боя с «глазом» ГСН, `aam 3` тяжёлая со сбрасываемым ускорителем) и блоки НАР (`rockets 1–3`), у всех балка-держатель с замками;
  - `ground_models.py` — ЗСУ, ЗРК, РЛС на одном вымышленном 4-осном шасси, по фото владельца (башня ЗСУ вращается, рама ЗРК поднимается при захвате, антенна РЛС крутится);
  - `tanker_boom.py` — заправщик Meshy + выдвижная штанга (узлы `Boom`, `BoomTube`, `BoomTip`);
  - `battle_lod.py` — облегчённая модель для боя из модели ангара (по умолчанию 9 000 треугольников, текстура 1024);
  - `erase_tail_marks.py` — стирает знаки на хвостовом оперении текстуры (правило 4);
  - `audit_models.py` — осмотр GLB: треугольники, куски, мусор, открытые края, три ракурса.
- Файлы .blend в проекте Claude: `/mnt/project-files/turrets3d/turret_kit.blend`, `turret_grach.blend` (утверждены 16.10), `/mnt/project-files/catalog/porcupine_concept.blend` (турель «Дикобраз», утверждена 16.10).
- Модели турелей до Blender-версии (Meshy и кодом в Godot) отклонены.

### 2.4. Конвейер подготовки: `game/tools/model_lab/`
Команды — в начале `model_lab.gd`. Шаги для модели из генератора:
1. `roll_glb.py` — поворот (Hunyuan кладёт самолёт на бок; Meshy — наземку).
2. `model_lab.gd -- prep` — оси, масштаб (длина 1), центр, бюджет треугольников (`--budget`, по умолчанию 15 000), `--nose=`, `--ground`.
3. `fit_span.py` — подогнать размах под спрайт (нужно было для TRELLIS и Hunyuan).
4. `decimate_glb.py` — упрощение до бюджета и текстуры не больше 2048.
5. `model_lab.gd -- preview` — снимок сверху рядом со спрайтом (нужен `xvfb-run`).
Ещё: `biome_prep.py` (B-41: модели биома — упрощение, текстуры ≤ 1024, цвет под палитру стайл-гайда; нужны `pymeshlab`, `trimesh`), `bake_impostor.gd` (картинки для облегчённых деревьев-«карточек» на пресетах ниже «Максимального»), `sprite_top.gd`, `trellis_gen.py` (TRELLIS.2, больше не используется).

## 7. Что не получилось и почему
- **TRELLIS.2** (MIT, через HF, 14.10): крыло уже нужного (размах 0,55 длины вместо 0,75), «зубцы» текстуры при увеличении ×4, модель цельная, второй seed — сломанный самолёт. Причина — вход 170×128 пиксельный спрайт строго сверху. Бесплатная квота 1–2 генерации в день.
- **Hunyuan 3D** (14.10): заметно лучше TRELLIS, но самолёт приходит на боку, размах меньше (0,62 → растягивали ×1,28). Kirill выбрал Meshy как основной. PR #2 «Hunyuan как основной» закрыт как устаревший.
- **ЗСУ кодом в Godot** (14.10): 468 треугольников, спрайт как текстура, стволы нарисованы на корпусе. Заменена Blender-версией по фото.
- **Турели из Meshy и примитивов** (15–16.10): «висели в воздухе» на «Ките», у «Грача» стояли на хвосте; три варианта (живые стрелки / дистанционные / смешанный) — «всё ещё очень плохо». Решение — Blender по фото.
- **ЗРК и РЛС из Meshy**: «модель неприменима» (каталог 6.1–6.2) → Blender по фото.
- **Ракеты, НАР, ловушки, кассеты из простых фигур** — отклонены в каталоге (3.1–3.5): нужны модели по реальным примерам, ступени меняют форму, длину и детали, а не только размер.
- **Текстура подвеса «Грача»** пробивала крыло — исправлено в PR #22.

- **Gemini** не запускается у Kirill в регионе; Qwen-Image-Edit (Apache 2.0) предлагали, не выбрали.
- **Камикадзе** выведен из игры (модель — основа для ракеты); **пушечная гондола** убрана из пула (может вернуться).

- **Облако не меряет FPS**: замеры только по логам с реальных ПК (3.4-t1: 37–38 FPS с первой минуты у Kirill; тормозит 3D-сцена, ~1300 вызовов отрисовки, рывки подгрузки рельефа до 0,1 с).
