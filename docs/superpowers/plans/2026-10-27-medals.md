# Medals with small bonuses («Наградная планка») — plan

Kanta 2026-10-27: option 1 of the card «Какую систему достижений делаем?» — medals with small always-on bonuses.
Proposal page (its header says 39 achievements; the rows are 38 medals, 91 tiers; caps): https://claude.ai/artifact/SFpbNdWo8e39bFeEf7mKj6. Backlog: MD-01.

## Rules

- Achievements count over the whole game (profile), not one sortie. A tier is reached once and stays.
- Each tier gives a small permanent bonus (or nothing for picture-only medals). Bonuses always on.
- Caps over all medals together: damage +10 %, HP +10 %, parts +10 %, reload/cooldown −10 %.
- A tier is earned at the end of a sortie (death, evacuation or exit after ≥ 30 s), never mid-flight: the
  result screen shows «Новая медаль» with the picture. The «Битва асов» test mode does not count (no award there).
- Hangar tab «НАГРАДЫ»: all medals as a board, each with its picture in the reached metal (grey when none),
  name, condition, bonus, and a bar to the next tier. Hidden medals show «?» until earned.
- Not in the Next Fest demo build (`Demo` hides the tab and skips the award). Steam achievements later,
  after the app is registered (each tier = one Steam achievement).

## Where it lives

1. `game/scripts/balance/medals.gd` (`MedalBalance`) — pure data and rules (TDD, `game/tests/medals_test.gd`):
   - `LIST`: id, group, counter key, tier thresholds, bonus key, bonus per tier, frame style, hidden flag.
   - `tier(value, thresholds)`, `bonuses(counters) -> {bonus_key: total}` with the caps, `new_tiers(before, after)`.
   - `run_counters(s) -> {key: add}` turns one sortie's stats into counter increments (pure, testable).
2. `Profile.data["medals"] = {"c": {counter: int}, "cards": [...], "syn": [...]}`; `Profile.medals_award(s)`
   called from `award_run`; returns the new tiers for the result screen. Old saves load with zero counters.
3. Bonuses are applied in `Profile.apply(p)` into `Player.mods` (existing keys where they exist: `dmg_all`,
   `ground_dmg`, `blast_r`, `blast_dmg`, `turret_traverse`, `wing_hp`, `roll_time`, `taken_k` …) plus a few
   new keys read at one place each: `boss_dmg` (Enemy.damage), `tail_k` (PlayerGuns.gun_damage), `parts_k`
   (RunState parts), `boss_parts` (kill of a boss), `crew_xp_k` (award_run), `msl_cd`/`flare_cd`/`dive_cd`,
   `heal_k`, `fuel_k`, `xp_k`, `spread_k`, `convoy_dmg`, `fortress_spd`, `dive_time`, extra rerolls and bans.
4. Run stats: `Main` already keeps kills, bosses, `kills_by` (kind), `dealt` (source), `tail_kills`,
   `near_misses`, hits, telemetry (`dive_uses`, `dive_dodged`, `fuel_refuels`, `convoy_done`, `fortress_base`,
   `healed`). New per-run counters only where nothing exists: kills by weapon class (from `Enemy.last_src`),
   flared enemy missiles, fortress kills.
5. Art: `tools/medals/make_medals.py` writes vector SVGs `game/art/medals/<id>.svg` (one emblem per medal,
   four frames: round medal on a ribbon, gear patch, shield, class badge). The tier metal (bronze, silver, gold,
   banner) is drawn at runtime by tinting a grey-scale texture plus the ribbon bars; grey when not earned.
   Fictional: no real orders, stars or insignia.
6. UI: `HudHangar` tab «НАГРАДЫ» (`HudMedals` drawing class), result screen line in `HudResult`.
   Strings via `Loc.t` and `en.po` / `zh_CN.po`.

## Not in this step

demo counter carry-over.
